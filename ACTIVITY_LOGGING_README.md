# Activity Logging Implementation

This document explains the activity logging system that automatically tracks user activities when they end ChatActivity, MeetingActivity, or VoiceNoteActivity.

## Overview

The system automatically logs activities to the backend API when users finish using different features of the app. It uses the GeminiHelper class to generate intelligent descriptions of what the activity was about.

## Components

### 1. Models
- `ActivityRequest.java` - Request model for activity logging API
- `ActivityResponse.java` - Response model from activity logging API

### 2. API Integration
- Updated `AuthApi.java` with activity logging endpoint
- Uses existing `ApiClient.java` for network communication

### 3. Activity Logger Utility
- `ActivityLogger.java` - Main utility class that handles activity logging
- Supports three activity types: Chat, Meeting, Voice Note
- Integrates with GeminiHelper for intelligent description generation

## API Endpoint

**Activity Logging Endpoint:** `POST http://localhost:8080/users/{userId}/activity`

**Request Body:**
```json
{
  "type": "Voice Note",
  "title": "Talking about gym", 
  "description": "5km morning run in the park"
}
```

**Response:**
```json
{
  "id": "68eaa1f48577b224a6fbf909",
  "createdAt": "2025-10-11T13:29:08.1899802",
  "type": "Voice Note",
  "title": "Talking about gym",
  "userId": "68ea9effc0ececee417bd2fc",
  "description": "5km morning run in the park"
}
```

## How It Works

### 1. ChatActivity
- **Trigger:** When the activity is destroyed (user exits chat)
- **Content:** Captures the first 5 messages from the chat conversation
- **Title:** "Chat Session"
- **Description:** Generated by Gemini based on chat content

### 2. MeetingActivity  
- **Trigger:** When the activity is destroyed (user ends meeting)
- **Content:** Captures the full transcript from `transcriptTv`
- **Title:** "Meeting Session"
- **Description:** Generated by Gemini based on meeting transcript

### 3. VoiceNoteActivity
- **Trigger:** When the activity is destroyed (user exits voice note creation)
- **Content:** Captures text from `editTextMessage`
- **Title:** "Voice Note Creation"
- **Description:** Generated by Gemini based on note content

## Gemini Integration

The system uses GeminiHelper to create intelligent descriptions:

1. **Prompt Creation:** Builds context-aware prompts based on activity type and content
2. **Description Generation:** Gemini creates concise summaries (max 50 words)
3. **Fallback Handling:** If Gemini fails, uses simple fallback descriptions
4. **Content Cleaning:** Removes quotes and trims generated descriptions

## Usage Examples

### Manual Activity Logging
```java
// Log a chat activity
ActivityLogger.logActivity(context, ActivityLogger.ActivityType.CHAT, "Chat Session", chatContent);

// Log a meeting activity  
ActivityLogger.logActivity(context, ActivityLogger.ActivityType.MEETING, "Meeting Session", transcript);

// Log a voice note activity
ActivityLogger.logActivity(context, ActivityLogger.ActivityType.VOICE_NOTE, "Voice Note Creation", noteText);
```

### Activity Types
```java
ActivityLogger.ActivityType.CHAT        // "Chat"
ActivityLogger.ActivityType.MEETING     // "Meeting" 
ActivityLogger.ActivityType.VOICE_NOTE  // "Voice Note"
```

## Features

- **Automatic Logging:** Activities are logged automatically when users exit activities
- **Intelligent Descriptions:** Uses Gemini AI to generate meaningful activity summaries
- **User Context:** Uses stored user ID from SharedPreferences
- **Error Handling:** Graceful fallbacks if Gemini or API calls fail
- **Content Filtering:** Only logs activities that have actual content
- **Async Processing:** All API calls are handled asynchronously

## Security & Privacy

- **User Authentication:** Uses stored user ID from login session
- **Content Privacy:** Activity content is processed by Gemini for summarization
- **Network Security:** Uses existing cleartext traffic configuration for localhost
- **Error Logging:** Comprehensive logging for debugging without exposing sensitive data

## Error Handling

The system handles various error scenarios:

1. **Missing User ID:** Logs error and skips activity logging
2. **Gemini API Failure:** Falls back to simple descriptions
3. **Network Errors:** Logs error but doesn't crash the app
4. **Empty Content:** Skips logging if no meaningful content exists

## Integration Points

The activity logging is integrated at the `onDestroy()` lifecycle method of each activity:

- **ChatActivity.onDestroy()** → `logChatActivity()`
- **MeetingActivity.onDestroy()** → `logMeetingActivity()`  
- **VoiceNoteActivity.onDestroy()** → `logVoiceNoteActivity()`

This ensures activities are logged when users naturally exit the features, providing accurate usage tracking.
